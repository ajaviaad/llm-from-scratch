# Build a language model from first principles

This repository implements a small decoder language model in NumPy, including its backward pass and optimizer. You supply text, turn it into token IDs, fit all model parameters, save the training state, and generate a continuation. No pretrained weights or automatic-differentiation framework are needed for that path.

The model is intentionally small enough to inspect on a CPU. “From scratch” describes how it is implemented and trained; it does not imply the capability or scale of a commercial assistant. The [training guide](training.md) provides the supported commands. This guide explains the computation those commands perform.

## 1. Text becomes an integer prediction problem

A tokenizer maps text to a sequence of integer IDs. The byte tokenizer uses the UTF-8 encoding of the text, giving a base vocabulary of 256 possible byte values. One character may occupy several bytes. A byte token is therefore not always a complete character, and an arbitrary generated byte sequence need not be valid UTF-8.

Byte-pair encoding, or BPE, learns frequent adjacent-pair merges from training text. It begins with bytes and builds larger pieces; its learned merge rules become part of the model's input contract. A BPE model and a byte model cannot share a checkpoint merely because their hidden dimensions match. The tokenizer determines the vocabulary, embeddings, output logits, and the meaning of every token ID.

This BPE implementation begins with all 256 byte values, learns frequent adjacent-pair merges within documents, and applies the learned rules in merge order. It performs no text normalization and adds no special tokens. Its deliberate size limits are documented in the training guide.

Use training text alone to learn any tokenizer merge rules. Encoding validation text with those frozen rules is allowed; using validation text to learn them changes the evaluation boundary. Preserve document boundaries when constructing examples so an accidental join does not teach a relationship that never existed.

For a token sequence `[a, b, c, d, e]`, a four-position training example is:

```text
inputs:   [a, b, c, d]
targets:  [b, c, d, e]
```

The target at every position is the next token. A causal mask allows position 2 to use input positions 0, 1, and 2, while blocking later inputs. The target token is present elsewhere in a shifted training array, so correct masking is essential.

## 2. Token and position embeddings create a residual stream

An embedding is a learned table with shape `[vocabulary, width]`. Looking up the IDs of a batch with shape `[batch, time]` produces `[batch, time, width]`. The model adds a learned position vector at each position. Its initial residual stream is:

```text
x = token_embedding[token_ids] + position_embedding[position_ids]
```

The word *residual* describes a path that later sublayers add to rather than completely replace. Position embeddings distinguish order. A cache continuation must use the next position offset, not restart at zero.

The implementation uses learned absolute positions. A separate discussion of RoPE, a different positional method, would not make these checkpoint parameters rotary. A change of positional method requires an explicit architecture and compatibility change.

## 3. Each decoder block mixes context, then transforms features

The main forward path is:

```text
input token IDs
    -> token lookup + learned positions
    -> RMSNorm -> causal multi-head attention -> residual addition
    -> RMSNorm -> SwiGLU feed-forward network -> residual addition
    -> repeat the configured decoder block pattern
    -> final RMSNorm
    -> vocabulary projection
    -> next-token logits
```

The default configuration has two blocks, a 32-token context, residual width 16, two attention heads, and feed-forward width 32. All parameters are trained. The [training guide](training.md) lists the supported configuration fields. The definitions below apply to each block; the number of blocks determines how often they are composed.

### RMSNorm: control magnitude along the feature axis

For a feature vector `x`, RMSNorm computes:

```text
r = 1 / sqrt(mean(x * x) + epsilon)
y = x * r * learned_scale
```

The mean is over the features of one token, not over the batch or sequence. Unlike LayerNorm, this operation does not subtract the mean. Epsilon prevents division by zero for a zero vector and affects behavior near zero. Learned scales are trainable parameters; `r` is an intermediate value for this input.

### Attention: address values using queries and keys

Three projections produce queries, keys, and values. Reshaping separates the head axis:

| Quantity | Shape |
| --- | --- |
| Residual stream | `[batch, time, width]` |
| Queries | `[batch, heads, query_time, head_width]` |
| Keys and values | `[batch, heads, key_time, head_width]` |
| Attention scores and weights | `[batch, heads, query_time, key_time]` |
| Joined attention output | `[batch, query_time, width]` |

The model requires `width` to be divisible by `heads`. Each head computes `Q @ K.T / sqrt(head_width)`. The causal mask replaces disallowed scores with negative infinity; stable softmax turns each allowed row into weights that sum to one. Subtracting the largest score before exponentiation preserves probabilities while avoiding large positive exponentials.

The weighted values are joined, projected back to the residual width, and added to the input. Head count changes the representation of the calculation; it is not an independent guarantee of quality.

### SwiGLU: a learned gate on feature expansion

The feed-forward network creates an up branch and a gate branch:

```text
up = normalized_x @ W_up
gate = normalized_x @ W_gate
activated_gate = gate * sigmoid(gate)
update = (activated_gate * up) @ W_down
output = attention_residual + update
```

The two expanded branches have the configured feed-forward width. Their elementwise product returns through a down projection. This is a per-token transformation: mixing information across positions happened in attention. Both branches receive gradients.

### Vocabulary projection: one logit per candidate token

After final normalization, an untied output matrix maps residual features to vocabulary logits. A logit is an unnormalized score, not a probability or a confidence guarantee. The output projection and the token embedding table are separate learned parameters in this implementation.

## 4. The objective is mean next-token negative log likelihood

For the target token at one position, loss is:

```text
log(sum(exp(logits))) - target_logit
```

The implementation uses a shifted form of this expression for numerical stability. Training averages over the selected batch and time positions. Loss is measured in natural-log units per token. For a perfectly uniform distribution over 256 byte tokens, it is `log(256)`, approximately 5.545. That number is a reference for the byte vocabulary, not a universal starting loss.

Perplexity is `exp(loss)` when the same mean token loss is used. Tokenization changes the unit being averaged. A BPE perplexity and a byte perplexity are not directly comparable; neither is automatically comparable with a published result using another tokenizer or evaluation dataset.

## 5. Backpropagation is written explicitly

The backward pass walks the forward computation in reverse. It keeps a *tape*: the intermediate arrays needed to calculate derivatives. This is ordinary data stored by the implementation, not an automatic-differentiation engine.

The cross-entropy gradient with respect to logits is `(probability - one_hot_target) / number_of_targets`. For a projection `Y = X @ W`, gradients are `dW = X.T @ dY` and `dX = dY @ W.T`, after flattening the batch/time axes where appropriate. A residual addition sends the incoming gradient down both branches and adds the contributions when they meet again.

For a softmax row `a` and its incoming gradient `da`, the score gradient is:

```text
ds = a * (da - sum(da * a))
```

The sum is over the key axis. The backward pass then differentiates both score inputs (`Q` and `K`) and the weighted value path (`V`). Masked positions have zero attention weight and contribute no score gradient in this path.

For SwiGLU, the derivative of `gate * sigmoid(gate)` is `sigmoid(gate) + gate * sigmoid(gate) * (1 - sigmoid(gate))`. The up and gate branches accumulate into the same normalized input. RMSNorm contributes both a direct scaled gradient and the derivative of its mean-square denominator.

Embedding lookup needs accumulation. If the same token ID occurs several times, its table row receives the sum of all those contributions. Overwriting the row would silently discard learning signals. Position rows also accumulate across batch examples at the same position.

A finite-difference check compares these analytic gradients with a small two-sided perturbation of the loss. It checks local derivative correctness; it is too expensive for ordinary training and does not replace validation of the overall task. The [experiment guide](experiments.md) includes a complete probe you can run and modify.

## 6. Adam updates parameters and maintains state

Adam retains a moving average of gradients and squared gradients for every parameter. Bias correction compensates for their zero initialization. The update divides the corrected first moment by the square root of the corrected second moment plus a small stabilizer.

Global gradient-norm clipping scales all gradients together when the norm exceeds its limit. It bounds an update input without changing the direction of the combined gradient. The logged norm before clipping helps identify spikes. This implementation's optimizer is Adam without weight decay; it should not be described as AdamW.

A training checkpoint therefore needs more than weights: model configuration, tokenizer identity/state, optimizer moments, step count, learning rate, random-generator state, and data identity matter for continuation. A new optimizer with old weights begins a different optimization trajectory. The [training guide](training.md) describes the actual artifact format and resume path.

## 7. Generation reuses key/value state

A prompt first runs through the full decoder. The final position's logits select a next token. Greedy decoding takes the highest logit; positive-temperature sampling draws from a probability distribution. The chosen token is appended and the process repeats within the supported context limit.

The key/value cache stores prior attention keys and values so the next step can append new ones. Correct cached decoding and a full recomputation should produce matching next-token logits for the same prefix, positions, and weights. Matching only the selected token is a weaker check because quite different logits can have the same maximum.

Context limits are explicit. The small model's learned position table does not magically extend to a longer prompt. Do not silently drop old tokens or reset positions and claim equivalence; a sliding-window policy would be a separate implementation with its own tests.

## Reading the implementation

Read [`llm_lab/model.py`](../llm_lab/model.py) in this order: configuration, forward pass, loss/backward pass, optimizer, batch construction, evaluation, checkpointing, generation. Then follow the tokenizer and command interfaces linked by the [README](../README.md). Inspect array shapes at one batch before changing dimensions.

The repository's purpose is to make these steps executable and understandable together. The [limitations](limitations.md) identify what would need to change before a larger training run or a deployment claim.
